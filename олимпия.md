## Executive Summary

Сайт-оригинал olympiaperm.ru (1С-Битрикс) технически силён живыми данными (загрузка бассейна/фитнеса, свободные шкафчики видны на всех страницах), онлайн-покупкой и разветвлённой сеткой услуг, но информационная архитектура деградировала: раздел «Инфо» превратился в свалку из ~20 разнородных страниц, крошки Битрикса ломаются (текущая страница — `<a>` без `href`, у карточек специалистов пропущен уровень центра), новости попадают не в свою рубрику (например, страница `/news/kineziterapiya/` физически хранит контент о плавательных соревнованиях). У аквааэробики нет канонической страницы — она задвоена в «Бассейнах» и в «Фитнесе», а «заморозка карты» разбросана по трём разным меню.[^1][^2][^3][^4]

Редизайн (kidw3st.github.io/olympia/redesign/) уже задал сильный визуальный мир (пилюльная нави, тональные слои, Unbounded/Onest, волновой знак), и его нельзя ломать. Но с точки зрения IA и функциональности он де-факто откатился к плоской структуре: пять центров (`pools/`, `fitness_center/`, `spa_center/`, `swimming_center/`, `center_kinesitherapy/`) содержат вложенные листовые страницы, однако хлебные крошки на этих листьях состоят только из двух звеньев — «Главная → Название листа», без промежуточного узла центра. Например, страница `pools/aqua/index.html` (Аквааэробика) даёт крошки `Главная → Аквааэробика`, минуя «Бассейны». Служебные страницы (`faq/`, `pravila/`, `fz152/`, `personal-data-consent/`, `podarochnaya-karta-ideya-dlya-podarka/`, `vpervye-v-olimpii/`) лежат прямо в корне без общего хаба «Посетителям». В редизайне нет живой загрузки, мегаменю услуг, сравнения клубных карт, фильтров расписания, личного кабинета и виджета «первый визит» как сценария (виден лишь как одиночная страница).

Семь решений, дающих максимум эффекта:

1. Добавить в крошки редизайна промежуточный узел центра (`Главная → Бассейны → Аквааэробика`) — правится в шаблоне без визуальных изменений.
2. Собрать раздел «Посетителям» как физический URL-хаб (`/visitors/`) для FAQ, правил, парковки, кафе, первого визита, доступности, налогового вычета, вместо разбросанных корневых страниц.
3. Сделать «Цены» и «Расписание» самостоятельными хабами с фильтрами (день/зал/уровень/возраст/тренер), а не текстовыми простынями.
4. Ввести сравнение клубных карт «Плавание / Фитнес / Фитнес+Плавание» в виде таблицы-конструктора с льготами, вместо трёх одинаковых карточек.
5. Спроектировать (пока без реальных данных, каркас на статике) виджет живой загрузки бассейна/фитнеса/шкафчиков — сильнейшая фича оригинала, отсутствующая в редизайне.
6. Создать единый сценарий «Я здесь впервые» с пошаговым флоу, а не единичной информационной страницей.
7. Развести «Новости» (эксплуатационные объявления: режим работы, техперерывы) и «Акции» (маркетинг: скидки, розыгрыши) по разным рубрикам с чёткой таксономией по направлениям.

### Правила хлебных крошек

Крошки = раздел = URL = тематика: каждый уровень дерева должен физически отражаться в URL и в тексте крошки. Формат: `Главная → [Направление] → [Подраздел] → [Лист]`. Для листьев глубже трёх уровней (например, специалист) добавляется четвёртый уровень центра.

JSON-LD `BreadcrumbList` для типовой вложенной страницы (карточка специалиста SPA):

```json
{
  "@context": "https://schema.org",
  "@type": "BreadcrumbList",
  "itemListElement": [
    {"@type": "ListItem", "position": 1, "name": "Главная", "item": "https://olympiaperm.ru/"},
    {"@type": "ListItem", "position": 2, "name": "Команда", "item": "https://olympiaperm.ru/team/"},
    {"@type": "ListItem", "position": 3, "name": "SPA-центр", "item": "https://olympiaperm.ru/team/spa-tsentr/"},
    {"@type": "ListItem", "position": 4, "name": "Одирматова Лола", "item": "https://olympiaperm.ru/team/spa-tsentr/odirmatova-lola/"}
  ]
}
```

### Разбор конкретных ошибок

- **Дубль аквааэробики**: страница физически существует и в `/pools/aqua/`, и по логике фитнес-услуг; закрепить каноном за бассейнами (это водная активность), в фитнес-разделе оставить только карточку-ссылку с `rel=canonical` на `/pools/aqua/`.
- **Заморозка карты в трёх меню**: должна жить одним каноном в `/price/freeze/` (внутри хаба «Цены и карты»), а ссылки на неё — из бассейнов, фитнеса и посетителям — вести на этот единственный URL.
- **Новости не в своей рубрике**: ввести обязательное поле «рубрика» при публикации новости, привязанное к направлению, а не к тому, кто физически загрузил материал.
- **Команда: пропуск уровня центра**: в редизайне у листа специалиста сейчас крошки `Главная → ФИО` — добавить промежуточный узел `Команда → [Центр]` во всех карточках специалистов (72 карточки в /team/, судя по числу ссылок).
- **Служебные страницы в корне редизайна**: `/faq/`, `/pravila/`, `/fz152/`, `/personal-data-consent/`, `/vpervye-v-olimpii/`, `/podarochnaya-karta-ideya-dlya-podarka/` — физически лежат в корне сайта kidw3st.github.io/olympia/redesign/, без общего родителя; перенести под `/visitors/` и `/legal/` с сохранением текущих HTML-файлов через редиректы или простое перемещение папок.
- **aria-current="page" на «Направления»**: пункт «Направления» в текущем меню — якорная ссылка `#dirs`, а не отдельная страница, поэтому баг проявится только если реализовать `/pools/`, `/fitness_center/` и т.д. как переходы с активным табом «Направления» в шапке; при внедрении финальной навигации нужно явно исключать `aria-current` для якорных пунктов, иначе на всех пяти страницах направлений таб «Направления» будет ложно маркирован как активный одновременно с текущим листом.

## SEO

Кластеры запросов по Перми: коммерческие («абонемент бассейн Пермь», «купить клубную карту фитнес Пермь»), информационные («правила посещения бассейна», «что взять на первое занятие плавания»), локальные («бассейн ул. Мира 41», «фитнес Индустриальный район Пермь»), брендовые («Олимпия Пермь официальный сайт»).

Шаблоны мета для хабов и листьев:

- Хаб направления: `Title: {Направление} в Перми — {ключевая характеристика} | Олимпия`; `H1: {Направление}`; `Description: {направление за 1 фразу} на ул. Мира, 41. Цены, расписание, запись онлайн.`
- Лист услуги: `Title: {Услуга} — {Направление} | Спорткомплекс «Олимпия», Пермь`; `H1: {Услуга}`; `Description: {что это и для кого} в спорткомплексе «Олимпия». Запись и цены на сайте.`
- Карточка специалиста: `Title: {ФИО} — {должность} | Команда «Олимпии»`; `H1: {ФИО}`.

Schema, обязательная к внедрению: `SportsActivityLocation` + `Organization` + `LocalBusiness` на главной (частично уже реализовано), `BreadcrumbList` на каждой внутренней странице, `FAQPage` на `/visitors/faq/`, `Offer`/`PriceSpecification` на `/price/`, `Event` для соревнований (`/pools/grafik-sorevnovaniy/`), `Person` для каждой карточки специалиста, `ItemList` для страницы «Направления».

Технические долги индексации (перенос известных проблем оригинала): мягкие 404 на `/ads/…` и `/pormotion/…` нужно предотвратить в редизайне корректной настройкой 404-статуса и отсутствием опечаток в slug'ах при переносе контента; исключить из индекса дубли акций, параметры `print=`, `PAGEN`, версию для слабовидящих и `utm`-параметры через `canonical` и `robots.txt`.[^3]

## Маркетинг и конверсия

Первый экран редизайна («Вода олимпийского стандарта») силён для пловцов и спортсменов, но слаб для родителей и SPA-аудитории — нужен быстрый переключатель сценария («Я плыть / Я родитель / Я фитнес / Я SPA / Впервые») в первые 5 секунд просмотра, без изменения визуального языка (пилюли и тональные слои позволяют реализовать это как горизонтальный ряд пилюль-переключателей под главным дисплеем).

Триггеры конверсии: живая загрузка («сейчас свободно N дорожек», отсутствует в редизайне, критично для переноса), «сегодня открыто до 22:30» (режим работы уже зафиксирован в JSON-LD), явные льготы (пенсионеры/студенты/многодетные/участники СВО — упомянуты в акциях оригинала), подарочная карта, пробное занятие.[^3]

Новости vs акции: развести операционные объявления (изменение режима работы, техперерывы медкабинета) от маркетинговых акций (скидки, розыгрыши) по разным рубрикам с разными шаблонами карточек — в оригинале это смешано в одном фиде «Новости и объявления».[^3]

Ретеншн: мобильное приложение уже указано в футере редизайна (App Store/RuStore/Google Play ссылки присутствуют в `/faq/`) — нужно вывести его в отдельный блок на главной как канал повторных визитов, плюс программа лояльности SPA и TG-канал (уже есть `t.me/olympiaperm`).

Юридическое (ПДн, 152-ФЗ) должно оставаться доступным через футер и хаб `/legal/`, не занимая места в основной навигации — de-факто уже так реализовано в редизайне.

## Бэклог обновления редизайна

### Фаза 0 — быстрые правки текущих HTML

- Добавить промежуточный уровень центра в крошки всех листовых страниц (`pools/aqua/`, `fitness_center/gym/`, `spa_center/massazhi-telo/`, `center_kinesitherapy/pervichnyy-priyem/`, `swimming_center/mnm/`, все карточки `/team/{центр}/{фио}/`). Зачем: устранить путаницу навигации без изменения дизайна. URL: все листовые страницы пяти центров и команды. Критерий готовности: у каждого листа крошки состоят минимум из трёх звеньев. Зависимость: нет. Приоритет: P0.
- Убедиться, что `aria-current="page"` не проставляется одновременно на якорном пункте «Направления» и на текущем листе при будущем переходе с якоря на реальные страницы направлений. Зачем: избежать доступности-бага для скринридеров. URL: header во всех шаблонах. Критерий: только один активный `aria-current` на странице. Приоритет: P0.
- Физически переместить `faq/`, `pravila/`, `fz152/`, `personal-data-consent/`, `vpervye-v-olimpii/`, `podarochnaya-karta-ideya-dlya-podarka/` под `/visitors/` и `/legal/` с сохранением ссылок через редиректы. Зачем: убрать свалку в корне. Критерий: в навигации и футере отсутствуют прямые корневые ссылки. Приоритет: P0.
- Закрепить каноническую страницу аквааэробики за `/pools/aqua/`, убрать дубль в фитнес-центре или заменить ссылкой-указателем. Зачем: снять внутреннюю конкуренцию за SEO-вес. Приоритет: P0.

### Фаза 1 — структура разделов и шаблоны страниц

- Создать хаб `/visitors/` с карточками-ссылками на все служебные страницы вместо плоского списка. URL: `/visitors/index.html`. Критерий: единая точка входа во все «инфо»-страницы. Зависимость: Фаза 0 (перенос страниц). Приоритет: P1.
- Создать хаб `/timetable/` (уже частично есть подпапки `big-pool`, `group`, `mama-i-malysh`) с общей страницей-фильтром сверху. Критерий: единый URL с фильтрами по типу занятия. Приоритет: P1.
- Ввести рубрикацию новостей строго по направлениям (`/news/basseyn/`, `/news/fitness/`, `/news/spa/`, `/news/kinezioterapiya/`, `/news/company/`). Критерий: каждая новость физически лежит в папке своего направления. Приоритет: P1.
- Ввести хаб `/legal/` для ФЗ-152, ПДн, корпоратива, ДМС. Приоритет: P2.

### Фаза 2 — ключевые фичи

- Таблица сравнения клубных карт «Плавание/Фитнес/Фитнес+Плавание» на `/price/` с фильтром «есть льгота» (пенсионер/студент/многодетный/СВО). Критерий: пользователь видит все три карты и льготы в одной таблице без скролла по трём одинаковым карточкам. Зависимость: данные о ценах (JS оригинала, суммы не выдумывать). Приоритет: P0.
- Мастер записи в ЦДП: возраст → группа → расписание → форма. URL: `/zapis_cdp/`. Критерий: три шага без перезагрузки страницы. Приоритет: P0.
- Пошаговый флоу «Первый визит»: 4 экрана (что взять / медсправка / как доехать / первая покупка) вместо лонгрида. URL: `/visitors/first-visit/`. Приоритет: P1.
- Фильтры расписания (день/зал/уровень/возраст/тренер) на `/timetable/`. Приоритет: P1.

### Фаза 3 — живые данные, ЛК, приложение, загрузка

- Виджет живой загрузки бассейна/фитнеса/шкафчиков (заглушка → интеграция с API кассовой системы, как на оригинале). URL: sticky-блок во всех шаблонах. Приоритет: P0. Зависимость: техническая интеграция с системой доступа.
- Личный кабинет для проверки карты по штрихкоду, истории посещений, заморозки карты. Приоритет: P2. Зависимость: авторизация.
- Продвижение приложения (уже указано в футере) как отдельного канала на главной. Приоритет: P2.

## Чего не делать

- Не менять палитру, типографику (Unbounded/Onest) и тональные слои редизайна под «типичный фитнес-сайт».
- Не выстраивать три одинаковые карточки тарифов в ряд — только сравнительная таблица/конструктор.
- Не использовать bento-грид, неон, тени, псевдо-отзывы, иконки lucide — вразрез с уже заданным «own-world» брифом редизайна.
- Не хранить служебные страницы в корне без хаба «Посетителям» и «Юридическое».
- Не публиковать новости вне рубрики их направления.
- Не оставлять крошки специалистов без промежуточного уровня центра.
- Не выдумывать суммы цен — использовать плейсхолдеры до подключения реальных данных.
